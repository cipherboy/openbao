# CEL Support for Policies

## Summary

CEL-defined policies will give operators far greater control over requests
than existing ACL-based policies by using a more expressive language without
the need for server-side improvements to extend. This complements the rise of
CEL in the role systems of auth and secret engines and the possibility of an
external policy engine.

## Problem Statement

Existing ACL policies have not been expressive enough for many operators.

## User-facing description

This introduces a new policy type, `cel`, available under `sys/policies/cel`.
Like the existing `acl` policy type, `cel` policies are a default deny, but
any-one-pass-unless-explicit-deny behavior.
